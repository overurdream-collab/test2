# MCIAS — استئناف التنفيذ والتحقق

آخر عملية مكتملة قبل الاستئناف كانت PR34 عند `a0f5ed8`: نجاح60 اختبار PostgreSQL16 وCI، مع بقاء اكتمال المرجعيات غير مثبت. طابقت شجرة الفرع المحلي الشجرة المنشورة رغم اختلاف تاريخ النشر. لم يُنفذ reset أو merge، ولم يُكرر عمل G2/G4 أو إصلاح Pillow أو تجربة Windows. حُفظ استلام الحالة في `39f7021`.

## ما استؤنف فعليًا

- **G3 — `37cc61a`:** أضيف إصدار مجموعة مرجعية إلى نماذج الخدمة القائمة، مرتبط بصفوف G2 ومصدرها وبصمتها وعددها ونطاقها وفترتها، مع اعتماد Super Admin. الترحيل0019 ابن0018 الوحيد في هذا المسار. ثبت اختيار النسخة السارية تاريخيًا رغم وجود نسخة أحدث، وكشف العبث والعزل ومنع تعديل المرجع المعتمد.
- **G5 — `d0edc60` و`b18a83f`:** امتداد `run_audit(..., review_only=True)` داخل الخدمة وAuditSnapshot القائمين. تُحفظ النتائج الرسمية الأربع بإصدار2، مع قراءة تاريخية لا تخترع سببًا ولا تعيد كتابة السجل. مقارنة التعرفة تستهلك سلطة `exact/ceiling` صريحة؛ إثبات التكرار يتطلب هوية الخدمة كاملة ويستبعد المستقبل. نقص موعد الصرف اللازم يبقى غير محسوم.
- **Shared Audit — `328e629`:** واجهة واحدة لإسقاط معرفات المرجع والدليل والنسخة، ومطابقتها بالنتيجة المحفوظة، ومنع تكرار الحدث دون PHI. الحساب الاستشاري يبقى `held` و`payable=null` و`deductions=[]`؛ اختبار G6 يفتح حالة مراجعة ويسجل `hold` فقط.
- **المشرف:** رُبطت قراءة API بالتمثيل الرسمي مع إبقاء المصادقة والعزل وصلاحية القراءة. حُدث توقع رأس الترحيل إلى0019 بمساواة صريحة. يتضمن CI اختبارات المسار الأصلي وشهادات G3 والكاتب الجديد، ويحفظ المتوقع والفعلي والدليل في artifact.

ملفات المنتجين المركبة مطابقة بالبصمة لنسخ مالكيها وفق [manifest](evidence/E1_OWNER_SOURCE_MANIFEST.json). الملفات القديمة المعدلة في worktree `/workspace/g5` محفوظة دون لمس، ونسخ المنتجين المستخدمة لاختبار G5 مستثناة من Commit مالكه.

فشل اختبار الاستعادة أولًا بـ`FileNotFoundError: pg_dump` على المضيف. استُخدم العميل الحقيقي PostgreSQL16 داخل الحاوية القائمة بواسطة موائم CLI محلي في `/workspace/pg16-client-bin`، وأعيد الاختبار الفاشل وحده: **1 PASS في5.55 ثانية**. لم يتغير الاختبار لإخفاء الفشل. قاعدة الترحيل `mcias_resume_migrations` محلية واصطناعية.

CI الجديد لـPR34 لم ينفذ عند كتابة Commit الشيفرة. يتابع المشرف HEAD المنشور ويثبت الروابط الفعلية في وصف PR34 وفي إيصال `.e2e-output/verified_ci_20261021.json` بعد التنفيذ؛ لا يُستدل بنجاح a0f السابق على الشجرة الجديدة.
