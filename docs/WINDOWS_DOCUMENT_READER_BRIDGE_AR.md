# MCIAS — ربط قارئ المستندات التجريبي بـ Windows

الحالة: **مكوّن معاينة محلي أولي — لا تدريب، لا اعتماد طبي، لا دمج في مسار القرار المالي**.

## موضعه في دورة العمل

1. يستقبل G2 ملف Excel للمطالبات، ويحفظ مصدره وبصمته كما هو.
2. تُرفَع الفواتير PDF مستقلةً وتُربط كل فاتورة بسطر المطالبة عبر مسار المرفقات القائم في Windows.
3. بعد اجتياز فحص سلامة المصدر في G2، يستطيع المستخدم **المصرح له بقراءة النص الطبي** طلب معاينة الفاتورة من مركز الأدلة. تسمح المعاينة أيضًا لصفحة مصوّرة واحدة حُجرت بسبب غياب نص قابل للاستخراج فقط، دون رفع حالة الحجر أو تجاوز فشل الفحص الأمني.
4. يجلب الخادم أصل PDF المشفّر ويتحقق من SHA-256؛ ثم يعيد استخدام منطق تحديد الأعمدة والسطور من التجربة المستقلة `scripts/document_reader_dynamic_layout_pilot.py` في فرع `feat/mcias-document-reader-isolated-pilot`.
5. المخرجات: حقول مرشحة مع الصفحة وموقع العنصر وبصمة المصدر؛ تبقى دائمًا **HUMAN_REVIEW** و**NOT_AUTHORIZED**، ولا تتصل بمسار قبول/رفض المطالبة.

## التفعيل المقصود والمؤقت

- افتراضيًا **معطّل**. يحتاج المشغّل إلى ضبط `MCIAS_DOCUMENT_READER_MODE=local_preview` بعد مراجعة الأذونات.
- PDF النصّي ذو الصفحة الواحدة يدعم معاينة أولية محلية دون OCR.
- PDF المصوَّر يحتاج `MCIAS_LOCAL_OCR=tesseract` وتثبيت محرّك Tesseract وحزمة اللغة المناسبة **محليًا**؛ حاوية Windows الحالية لا تحتوي على Tesseract. لا يتم تنزيل أي نموذج تلقائيًا.
- المستندات متعددة الصفحات أو المحمية بكلمة مرور أو غير المفهومة تعاد للمراجعة البشرية ولا تُخمَّن بياناتها.
- API: `POST /api/v1/ingestion/documents/{document_id}/reader-preview`. يجب أن يجتاز المستخدم `ingestion.read` **و** `medical_fields.text.read` ضمن المؤسسة نفسها. لا تُمنح صلاحية النص الطبي تلقائيًا لحسابات Windows.
- المعاينة مؤقتة وغير محفوظة في G2 أو G5، ولا ترسل البيانات إلى شبكة خارجية. ولا يُسمح لها بتعديل الحكم الآلي أو اعتماد أي مبلغ.

## حدود المرحلة الحالية

- منطق الأعمدة مقتبس من **تجربة محدودة على ملفات اصطناعية**، وليس نموذج ذكاء اصطناعي مدربًا أو قارئًا عامًا لكل فواتير المستشفيات.
- لا يجري هذا المكوّن **مطابقة رقم الفاتورة أو مبالغها ببنود Excel**، ولا يقارن أدوية/أشعة/تحاليل بالوثائق الداعمة. هذه عقدة تكامل لاحقة، بعد التحقق من الدقة ومرجعيات G3 الست.
- لا يكفي نجاح المعاينة لاعتبار الفاتورة دليلًا معتمدًا أو لسماح القرار الحتمي بقبول المطالبة.
- اختبار هذه المرحلة اصطناعي ومحلي. يجب إجراء تحقق صلاحيات PostgreSQL وواجهات Windows ثم تقييم عيّنة فواتير حقيقية مصرح بها قبل أي اعتماد إنتاجي.

## متابعة التطوير بعد تثبيت المكونات

1. توسيع معالجة PDF المتعدد الصفحات مع روابط أصلية لكل صفحة وصندوق.
2. إضافة مواءمة واضحة ومختبرة بين `claim_line_id` و`invoice_document_id` وقيم G4، مع إظهار تعارضات الأرقام والكمية والسعر والمستندات الناقصة.
3. اختبار عينات عربية وإنجليزية متنوعة وقياس الدقة ومناطق الخطأ؛ **التدريب لاحقًا** حسب توجيه المالك.
4. يبقى تدقيق القواعد مستقلًا عن تدقيق الذكاء الاصطناعي، ثم تُعرض نتائج المقارنة للمراجع البشري.
