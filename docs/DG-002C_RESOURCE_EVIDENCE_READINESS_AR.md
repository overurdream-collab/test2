## Evidence locator architecture — separate recognition from alignment

- Preserve **Paddle VLM recognition output** with provenance `PADDLE_VLM_TEXT` and **no cell bbox** if the model returns a page-wide block. Never re-label that bbox as a cell.
- Option A, **model-derived locator**: enable native Paddle layout/table detection, retaining each emitted block/row/cell polygon, model name, exact revision, input image SHA, page and transform. This is only a true model-derived field locator if the output actually resolves the value to a specific cell; document-level or whole-table boxes do not qualify.
- Option B, **independent alignment**: run a separately versioned region detector and local OCR token locator on the **same rendered source pixels**. Associate each Paddle value to candidate tokens/regions with script-aware normalization for matching only, geometry, row/column constraints, and explicit duplicate-amount ambiguity checks. Provenance `INDEPENDENT_OCR_ALIGNMENT`; never present it as a Paddle-predicted box. If independent OCR misreads an Arabic digit, do not force an alignment by trusting the Paddle text.
- For every proposed field: `document_id`, `organization_id`, `source_pdf_sha256`, `rendered_page_sha256`, `page_number`, `field_id`, `row_id`, `column_id`, `value_raw`, `value_normalized_for_matching`, `region_polygon_px`, `coordinate_system`, `image_width_height`, `render_transform`, `locator_method`, `locator_model_revision`, `ocr_model_revision`, `alignment_candidates`, `alignment_margin`, `status` and human-review reference. Derive identities and source hashes from the trusted G2 retrieval context, not client input.
- Independently reopen the original G2 encrypted PDF under authorized organization, verify PDF SHA-256 and page render SHA-256, validate polygons inside image bounds, exact page and row/column relationships, and verify that the region contains visible candidate text. Human transcription attestation is separate from medical correctness or financial entitlement. Any duplicate ambiguous value, page-wide box, unverified source, moved amount, missing quantity/date/price, non-unique alignment, mismatched organization or mismatched hash => `UNRESOLVED` / `HUMAN_REVIEW`.
- Evaluation requires **two independent axes**: exact critical-field text accuracy and field-to-source IoU / page / row / column accuracy. Gold must be authored separately and never used to pick predicted cells. Count reading errors, alignment errors and both, with abstention rate and false accepted rate. Include negative tests swapping equal-valued cells, moving line totals between rows, changing image render scale and altering source bytes.

## Medical Arabic evaluation design (synthetic only)

Use independent Arabic/English gold with realistic Arabic-only and mixed-script headers, Eastern/Western Arabic digits, decimal and thousands separators, right-to-left line order, abbreviations, different fonts and multiple rows. Distinct strata:
- **Medication:** drug generic/brand, strength, dose, unit, frequency, route, duration; e.g. `٥٠٠ ملغ` versus `٥٠ ملغ`, `مرة` versus `مرتين`. Exact entity + dosage/units, unsafe substitution rate.
- **Laboratory:** analyte, result, unit, reference range, high/low flags and decimal; paired row accuracy and clinically significant digit substitution.
- **Diagnosis and radiology:** anatomical site, modality, diagnosis text and negation (`لا يوجد` versus `يوجد`), uncertain finding and correct source paragraph. No automatic diagnostic judgment.
- **Invoice:** service, quantity, unit price, line total, dates, currencies and provider row identity; swapped amounts and duplicate totals are explicit locator adversarial tests.
Report per category and language: CER/WER, exact-field, entity+unit+row accuracy, IoU>=0.5 and IoU>=0.75, wrong-row rate, missing field, false acceptance, abstention, runtime and peak RSS/VRAM. Critical numeric/medication failures always human-review, regardless of aggregate CER.
