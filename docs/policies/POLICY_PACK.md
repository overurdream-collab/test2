# حزمة القرارات المالية والسياسات

معرّف الوثيقة: `MCIAS-POL-001` · الإصدار: 1.0 · الحالة: مسودة للمراجعة · اللغة: العربية

[English version](POLICY_PACK_EN.md) · [فهرس الحزمة](../ACCEPTANCE_PACK_INDEX.md)

## الغرض وحالة الاعتماد

هذه 13 **مسودة قرار مالي وتشغيلي جديدة**، وليست إعادة تسمية لسجل ADR المعماري ولا دليلًا على موافقة الجهة. معرّفات FIN-ADR مستقلة عن ADR-001…ADR-011. جميع القرارات أدناه `DRAFT / BLOCKED_FOR_PRODUCTION` إلى حين توقيع كل قرار ومطابقته مع التنفيذ. يستطيع التطوير التحضيري الاستمرار، لكن لا تُفعّل السياسة المالية المتأثرة قبل حل الفجوة.

المرجع الحاكم: [عقد القبول](../ACCEPTANCE_CONTRACT.md)، [سجل البوابات](../../GATE_STATUS.md)، [تغطية الواجهة/API](../FRONTEND_ROUTE_API_MATRIX.md). نجاح CI لا يوقّع أي قرار.

## آلية الاعتماد وإدارة التغيير

1. يراجع مالك السياسة المالية كل قرار والبدائل والأمثلة المرجعية.
2. يثبت المراجع المستقل الاتساق القانوني والمحاسبي والبيانات المطلوبة.
3. يوقّع رئيس الجهة أو المخول كتابةً القرار ونسخة السياسة وبصمة مستندها ونطاق المؤسسة وتاريخ السريان.
4. يراجع الفريق مطابقة القرار للمحرك؛ غير المدعوم يبقى BLOCKED حتى التطوير والاختبار. لا تُحل الفجوة بتغيير قيمة واجهة فقط.
5. يبقى المسؤول التقني منفّذًا محكومًا بالصلاحيات، وليس مصدر الموافقة. تحفظ النسخ السابقة وأثر التغيير والأدلة.

الحقول الإلزامية لكل قرار: المالك، تاريخ القرار، البديل المختار، المبرر، المؤسسة، رقم السياسة ونسختها، السريان، المستند وSHA-256، المراجع المستقل، المخول وتوقيعه، أثر التغيير، حالات القبول ونتائجها. لا توجد أسماء أو توقيعات معبأة سلفًا.

## FIN-ADR-001 — أولوية العقد والملحق وتاريخ السريان

- **المقترح:** اعتماد ترتيب صريح للعقد والملحق والاستثناء الموقّع، وربط المطالبة بالنسخة السارية في تاريخ الخدمة. لا يستبدل التعديل الرجعي النسخة القديمة؛ يلزم تقرير أثر ومراجعة.
- **التنفيذ الحالي وحدوده:** توجد نسخ عقود وفترات نصف مفتوحة [effective_from, effective_until)، ومنع تداخل العقود المعتمدة للمزوّد داخل المؤسسة. ترتيب الوثائق القانوني يحتاج قرار الجهة.
- **البدائل المطلوب حسمها:** العقد الأساسي دائمًا، أو أحدث ملحق موقّع، أو استثناء محدد؛ يجب معالجة التعارضات صراحة.
- **دليل القبول المطلوب:** عقد وملحق متعارضان، حدّ تاريخ انتهاء، وتعديل رجعي؛ مرجع قرار موثّق لكل نتيجة.
- **مرجع التنفيذ:** [`mcias/reference_service.py`](../../mcias/reference_service.py)

## FIN-ADR-002 — أهلية المستفيد والخدمة

- **المقترح:** تقييم الأهلية عند تاريخ الخدمة وفق فئة المستفيد والتغطية السارية؛ التعليق عند نقص المرجع أو الغموض، دون اتخاذ قرار علاج طبي.
- **التنفيذ الحالي وحدوده:** توجد تسجيلات مستفيدين زمنية وتصنيفات، ومنع تداخل التسجيلات. لا يوجد سجل سريري شامل أو قائمة خدمات وطنية مكتملة.
- **البدائل المطلوب حسمها:** الأهلية عند الخدمة أو الاستلام أو التسوية؛ المقترح تاريخ الخدمة ويحتاج توقيعًا.
- **دليل القبول المطلوب:** انتهاء/بدء التسجيل، رمز خدمة غير مربوط، وغياب دليل الفئة؛ لا يُعتمد مبلغ مع بيانات ناقصة.
- **مرجع التنفيذ:** [`mcias/reference.py`](../../mcias/reference.py)

## FIN-ADR-003 — أساس التسعيرة والكمية والضرائب

- **المقترح:** تحديد وحدة الخدمة وشمول الكمية والضرائب قبل اعتماد التعريفة، ومنع تحويل سعر الوحدة إلى قيمة مطالبة دون أساس موثّق.
- **التنفيذ الحالي وحدوده:** مرحلة tariff في المحرك الحالي سقف مبلغ بعد الاستبعاد، وليست خصم نسبة عامًا. المطالبة لا تحتوي أعمدة كمية/ضريبة معيارية؛ احتسابها يحتاج تطويرًا إذا طُلِب.
- **البدائل المطلوب حسمها:** سعر للوحدة، حزمة خدمة، أو إجمالي سطر؛ اختلاف الأساس قد يتطلب تعديلًا برمجيًا قبل الإنتاج.
- **دليل القبول المطلوب:** فاتورة متعددة الوحدات وضريبة وحزمة؛ أمثلة حساب مستقلة وموافقة مالية.
- **مرجع التنفيذ:** [`mcias/audit_engine.py`](../../mcias/audit_engine.py)

## FIN-ADR-004 — الاستبعادات والتفويض المكتوب

- **المقترح:** اعتماد قائمة الاستبعادات ومصدرها وتاريخها وحدودها، مع تفويض رئيس الجهة ومراجعة مستقلة؛ لا يمنح المسؤول نفسه سلطة تغييرها.
- **التنفيذ الحالي وحدوده:** المحرك يقبل مبلغ استبعاد غير سالب ويحدّه بالمبلغ المتبقي. تفعيل قواعد الإنتاج يستخدم سجل ثقة موقّع؛ تفويض سياسة G5 آلية مختلفة موثّقة أدناه.
- **البدائل المطلوب حسمها:** مبلغ ثابت أو نسبة أو قائمة خدمات؛ النسب/التفسير الطبي غير معمم في المحرك الحالي.
- **دليل القبول المطلوب:** تعديل غير مصرح، توقيع خاطئ، مصدر مختلف، واستبعاد يفوق المطالبة: رفض أو تعليق بلا خصم مزدوج.
- **مرجع التنفيذ:** [`mcias/production_authorization.py`](../../mcias/production_authorization.py)

## FIN-ADR-005 — ترتيب الخصومات وأساسها

- **المقترح:** مراجعة واعتماد السلسلة المتاحة: exclusion → tariff → cap → copay؛ تعمل كل مرحلة على المتبقي. ترتيب آخر غير مدعوم دون تغيير واختبارات.
- **التنفيذ الحالي وحدوده:** AuditPolicy.validate يرفض أي ترتيب آخر؛ لا تُنفّذ الحسابات المالية المعتمدة في JavaScript.
- **البدائل المطلوب حسمها:** حساب جميع الخصومات على الأصل أو ترتيب مختلف؛ قد يسبب اختلافًا ماليًا ولا يمكن اختياره من الواجهة الحالية.
- **دليل القبول المطلوب:** حالة تجمع المراحل الأربع، وإثبات claimed = total_deduction + payable، ومراجعة مستقلة Palermo-2.
- **مرجع التنفيذ:** [`mcias/palermo2.py`](../../mcias/palermo2.py)

## FIN-ADR-006 — السقوف وحدود التغطية

- **المقترح:** تحديد مستوى السقف والفترة وصاحب السقف. لا يُعرض سقف المطالبة الحالي على أنه سقف سنوي تراكمي للمستفيد.
- **التنفيذ الحالي وحدوده:** policy.cap اختياري ويحدّ مبلغ المطالبة المتبقي. لا يوجد دفتر سقوف سنوي تراكمي محكوم في هذا المحرك.
- **البدائل المطلوب حسمها:** سقف لكل سطر/مطالبة، أو للمستفيد سنويًا، أو للعقد؛ التراكمي يحتاج تنفيذًا إضافيًا.
- **دليل القبول المطلوب:** سقف صفر، غياب سقف، وتجاوز سقف؛ منع اعتماد قاعدة سنوية دون دفتر موثّق واختبار تزامن.
- **مرجع التنفيذ:** [`mcias/audit_engine.py`](../../mcias/audit_engine.py)

## FIN-ADR-007 — المشاركة والتحمل

- **المقترح:** اعتماد النسبة ومصدرها والمبلغ الذي تُطبق عليه. المتاح حاليًا نسبة من المتبقي بعد الاستبعاد والتعريفة والسقف.
- **التنفيذ الحالي وحدوده:** copay_percent يقبل Decimal بين 0 و100، ويُقرب مبلغ المشاركة قبل خصمه. التحمل الثابت/التراكمي ليس نموذجًا عامًا متاحًا.
- **البدائل المطلوب حسمها:** نسبة من الأصل، نسبة من المتبقي، أو تحمل ثابت؛ اختلاف المقترح عن المحرك يحتاج معالجة قبل التفعيل.
- **دليل القبول المطلوب:** 0% و100% وحدود التقريب ونسبة غير صالحة؛ تحديد حصة كل طرف دون استنتاج طبي.
- **مرجع التنفيذ:** [`mcias/audit_engine.py`](../../mcias/audit_engine.py)

## FIN-ADR-008 — الدقة والتقريب

- **المقترح:** تختار الجهة HALF_UP أو HALF_EVEN والدقة 0 أو 2 أو 4، وتوافق على التقريب في كل مرحلة؛ لا نفترض قاعدة محاسبية تلقائيًا.
- **التنفيذ الحالي وحدوده:** المحرك يستخدم Decimal، وقاعدة البيانات NUMERIC، وتُرسل المبالغ كسلاسل عشرية. اختلاف النتائج المتوقعة يحتاج مراجعة وتوقيعًا.
- **البدائل المطلوب حسمها:** التقريب في النهاية فقط أو في كل مرحلة؛ المتاح حاليًا في كل مرحلة.
- **دليل القبول المطلوب:** أنصاف وحدات ودقة العملة والجمع المستقل؛ مقارنة أمثلة مرجعية موقّعة لكل سياسة.
- **مرجع التنفيذ:** [`mcias/audit_engine.py`](../../mcias/audit_engine.py)

## FIN-ADR-009 — العملات والتحويل

- **المقترح:** اعتماد العملات المقبولة ومرجع رموزها. الفصل حسب العملة، وعدم جمع عملات مختلفة أو تحويلها دون سعر وصلاحية معتمدين.
- **التنفيذ الحالي وحدوده:** المحرك يرفض اختلاف عملة المطالبة والسياسة؛ لا يوجد FX معتمد. التحقق من ثلاثة أحرف ليس إثبات عضوية في ISO 4217.
- **البدائل المطلوب حسمها:** عملة واحدة، تجميع منفصل، أو دفتر تحويل؛ الأخير يتطلب بيانات وآلية إضافية.
- **دليل القبول المطلوب:** مطالبات بعملتين ورمز غير مدرج؛ لا يظهر إجمالي موحد مضلل.
- **مرجع التنفيذ:** [`mcias/reporting_g7.py`](../../mcias/reporting_g7.py)

## FIN-ADR-010 — الأدلة الناقصة والاستثناءات

- **المقترح:** تحديد المستندات المطلوبة حسب الخدمة والحد المالي، وتعليق الناقص مع حفظ الأصل، ومنع استبدال الأدلة القديمة صامتًا.
- **التنفيذ الحالي وحدوده:** توجد بصمات ومحددات صف/صفحة وحجر ومرفقات. المحرك يعلّق incomplete evidence، لكن واجهة تنزيل الأصل ليست API متاحة عامة.
- **البدائل المطلوب حسمها:** رفض فوري أو تعليق لطلب دليل أو استثناء موثّق؛ لا يُحوّل التعليق إلى قرار طبي تلقائي.
- **دليل القبول المطلوب:** أصل تالف محفوظ، مرفق من مؤسسة أخرى، اعتراض بلا دليل ثم بدليل؛ سلسلة مصدر كاملة.
- **مرجع التنفيذ:** [`mcias/claim_batches.py`](../../mcias/claim_batches.py)

## FIN-ADR-011 — التكرار والإشارات والتحليل

- **المقترح:** اعتماد تعريف التكرار وفترة المقارنة ومعدل الإنذارات المقبول. الإشارة طلب مراجعة وليست حكم احتيال أو خصم آلي.
- **التنفيذ الحالي وحدوده:** توجد كشف تكرار المصدر، وصنف تدقيق duplicates، وإشارات G8 ومراجعات بشرية. لا توجد منصة AI توليدية لاتخاذ قرارات ملزمة.
- **البدائل المطلوب حسمها:** تطابق تام أو قواعد متعددة الحقول أو تحليل إحصائي؛ كل نوع يحتاج مقامًا وأدلة ومعيارًا مستقلًا.
- **دليل القبول المطلوب:** تكرار حقيقي ومتشابه مشروع ومجموعات صغيرة؛ قياس false positives وتتبع نسخة المهمة والمراجع.
- **مرجع التنفيذ:** [`mcias/intelligence_g8.py`](../../mcias/intelligence_g8.py)

## FIN-ADR-012 — القرار والتسوية والاعتراض

- **المقترح:** تعريف المخول بالاقتراح والمراجعة والاعتماد والاعتراض وإعادة التدقيق. لا يعتمد المقترح نفسه، ولا يعد التحقق الحسابي صرفًا أو قرارًا طبيًا.
- **التنفيذ الحالي وحدوده:** G6 أحداث محكومة ونسخ غير قابلة للتعديل، وG7 تقارير ثابتة. لا توجد كل مراحل الاستئناف/تعيين المراجع أو API لتشغيل تدقيق G5 إنتاجي.
- **البدائل المطلوب حسمها:** مراجعة واحدة أو طبقات توقيع حسب القيمة؛ سير متعدد المستويات كامل يحتاج مطابقة مع التنفيذ قبل الاعتماد.
- **دليل القبول المطلوب:** موافقة/رفض ذاتي حتى بعد hold، اعتراض موثّق، تقرير قديم ثابت، ومطابقة المبلغ مع المحرك المستقل.
- **مرجع التنفيذ:** [`mcias/governance_g6.py`](../../mcias/governance_g6.py)

## FIN-ADR-013 — الاحتفاظ والسرية والإتلاف

- **المقترح:** اقتراح 7 سنوات، مع تحديد بداية العد والوقف القانوني والأدوار ونطاق السجلات وآلية الإتلاف المستقلة. يلزم اعتماد قانوني ومؤسسي مكتوب.
- **التنفيذ الحالي وحدوده:** الأرشفة الشهرية المحلية مشفرة وتتحقق من القراءة، لكنها محدودة بـ10,000 صف/128 MiB. تستثني سجلات النظام بلا actor؛ الحذف والتقسيم الآلي معطلان.
- **البدائل المطلوب حسمها:** مدة أطول وفق القانون أو حسب نوع السجل؛ الإتلاف لا يُفعّل قبل تطبيق legal hold والتحقق من الاستعادة.
- **دليل القبول المطلوب:** استعادة مستقلة وبصمات وعزل مؤسسات وفحص حدود الحجم؛ لا يعد تنظيف عدادات الطلبات حذفًا لسجل التدقيق.
- **مرجع التنفيذ:** [`docs/RETENTION_POLICY.md`](../../docs/RETENTION_POLICY.md)

## التفويض والتوقيع: ثلاثة مسارات لا تُخلط

- تفعيل قواعد الإنتاج: Ed25519 على حمولة JSON معيارية تربط المؤسسة والمخول والتفويض والقاعدة والمصدر وبصمته، وسجل ثقة محلي خارج طلب HTTP (`production_authorization.py`).
- التحقق من مستند تفويض منفصل: توقيع Ed25519 على بايتات المستند المطابقة لـSHA-256 (`authorization_signatures.py`)؛ لا نفترض أن كل مسار API يستدعيه.
- تفويض سياسة G5: HMAC-SHA256 على `organization_id|policy_fingerprint|approver_id|reviewer_id`، بمفتاح `MCIAS_G5_POLICY_VERIFICATION_KEY` تحت حيازة محلية (`audit_authorization.py`). هذه آلية هندسية قائمة تحتاج تقييم الجهة، ولا تعادل تلقائيًا توقيعًا قانونيًا شخصيًا.

لا تُرسَل المفاتيح الخاصة إلى المتصفح أو طلبات API أو الوثائق. الصورة الممسوحة أو الموافقة بالبريد لا تفعّل المحرك وحدها. يوثّق المسؤول القانوني أهلية المخول والمراجع وتُجهَّز الثقة خارج النظام عبر إجراء معتمد.
