# متطلبات الجهة والبيانات والتشغيل

معرّف الوثيقة: `MCIAS-POL-003` · الإصدار: 1.0 · الحالة: مسودة للمراجعة · اللغة: العربية

[English version](CLIENT_REQUIREMENTS_EN.md) · [فهرس الحزمة](../ACCEPTANCE_PACK_INDEX.md)

## مالكو المتطلبات

الجهة تعيّن مسؤولًا لكل بند وتاريخ تسليم ومرجع تحقق. حالة كل بند عند إصدار هذه المسودة: NOT_SUPPLIED / NOT_APPROVED. لا يفترض وجود بيانات حقيقية في المستودع.

| المجموعة | ما توفره الجهة | شرط التحقق |
|---|---|---|
| التفويض والسياسة | جهة الاختصاص، حدود التفويض، القرارات الـ13، نسخة السياسة والأمثلة والتوقيعات | هوية وسلطة المخول ومراجع مستقل وبصمة وسريان |
| العقود | provider_code، النسخة، السريان، الحالة، الملحق والمصدر | رمز مستقر؛ منع تداخل المعتمد؛ حسم الأولوية |
| التسعيرات | عقد/نسخة، service_code، المبلغ والعملة والفترة ووحدة التسعير | Decimal غير سالب؛ أساس الكمية/الضريبة محسوم |
| المستفيدون | token مستعار، الفئة، السريان، مرجع التسجيل | جدول ربط الهوية يُحفظ داخل الجهة؛ لا أسماء أو أرقام هوية في Git |
| المطالبات | claim_reference، beneficiary_token، provider_code، service_code، service_date، claimed_amount، currency | المطابقة مع الأصل والبصمة والصف/الصفحة؛ اختلاف الأعمدة يمر بخريطة معتمدة |
| الأدلة | الفواتير والمرفقات وتفويض المستند والملحقات | الإذن قبل الوصول؛ الأصل مشفر غير قابل للاستبدال |
| الرموز المرجعية | أنواع المزودين والخدمات والتصنيفات ورموز ICD/CPT/LOINC/SNOMED إن استُخدمت | تعريف الإصدار والترخيص وخريطة الربط؛ ليست كتالوجات جاهزة في النظام |
| التشغيل | منصة Linux/PG16، حساب ترحيل مستقل وحساب تشغيل، TLS، ماسح محلي، مفاتيح ومجلدات خاصة | تثبيت SHA، فحص الصلاحيات ونسخ احتياطي واستعادة |
| القبول | الحمل والتزامن/P95 وRPO/RTO ومتصفحات وإتاحة وصول | أهداف مكتوبة قبل القياس؛ لا أرقام مخترعة |

## قواعد النقل والجودة

1. تبدأ الاختبارات الخارجية ببيانات اصطناعية وقواعد جديدة منفصلة، ثم نطاق حقيقي مصرح به بعد اعتماد الخصوصية والسياسات ذات الصلة. لا تُخلط البيانات الاختبارية والحقيقية؛ لا يوجد source_type شامل لكل صف.
2. لا تُرفق الأسرار أو الملفات الطبية بـGitHub أو تقارير عامة أو خدمات سحابية خارج المؤسسة. النقل قناة مؤسسية مشفرة، مع بصمة وعدد ملفات وصفوف وإيصال استلام داخلي.
3. التواريخ ISO `YYYY-MM-DD`، الزمن UTC/ISO 8601، النص UTF-8، العملات رموز معتمدة؛ المبالغ سلاسل عشرية دقيقة لا float ولا فواصل آلاف. لا تحول عددًا مقربًا من Excel دون مراجعة.
4. تحدد الجهة خريطة أعمدة CSV/Excel/PDF، الصفحات/الصفوف المتوقعة، القيم الفارغة والتكرار والصفوف الحجرية. مطابقة 100% للعدد والبصمات هدف هندسي؛ حدود الجودة الطبية/OCR تحتاج اعتمادًا.
5. provider_code/service_code/category_id قيم من بيانات الجهة، وليست Enums وطنية نفترضها. احتفظ بالمعرفات الأصلية والنسخ دون تغيير UUID الداخلية.

## مصفوفة الصلاحيات المطلوبة

تحدد الجهة من يحمل profile.read، ingestion.read/upload، claims.read/import، reference.read/write/approve، reports.read/create/export، governance.*، policies.approve/review/revoke، retention.read/archive، ومِن يمنح كل `medical_fields.<source_column>.read`. القائمة أعلاه مجموعات مراجعة وليست ضمانًا بأن كل اسم نجمي إذن صالح؛ تطابق مع ملفات API ومصفوفة التغطية. super_admin وحده لا يمنح كل صلاحية ولا يتجاوز استقلال المراجع.

## الاستلام والفجوات

لكل تسليم سجل: مالك، نسخة، صلاحية الاستخدام، قناة النقل، عدد الصفوف، SHA-256، أخطاء الحجر، نتائج الربط، قرار القبول/الرفض، المراجع والتاريخ. أحكام كمية/ضرائب وسقوف تراكمية أو دفتر insurer reconciliation أو مراحل استئناف كاملة غير موجودة تحتاج طلب تطوير منفصل. غياب API لتشغيل G5 إنتاجي يمنع افتراض أن البيانات والسياسة الموقعة وحدهما تكفيان لإطلاق التدقيق المالي.
