# G3 — اكتمال مرجعيات E1 من مصادر G2 القائمة

تاريخ الاستئناف: 2026-10-21. أساس العمل: PR #34، `a0f5ed864dad35a415e7173aea82c1b0441b07d8`، وشجرة عمل G3 المعزولة. هذه إضافة إلى التنفيذ القائم، دون مستورد أو سجل صفوف بديل.

## العقد المنفذ

العائلات الست مأخوذة من `REFERENCE_FAMILIES` والعقد المعتمد: `beneficiary`, `contract`, `tariff`, `policy`, `caps`, `history`.

- الجدول الجديد الوحيد `reference_dataset_versions` يربط المؤسسة والمالك والعائلة والمفتاح والإصدار وفترة السريان وفترة التغطية والنطاق وعدد الصفوف المتوقع بمستند G2 ومهمة استخراجه وبصمة SHA-256 وبصمة manifest والصفوف.
- صفوف المصدر تبقى في `ExtractedSourceRecord`. يستقبل G2 القائم CSV بعمودي `record_key,payload`؛ يحتوي `payload` على JSON مضبوط النوع. لا يُستنتج الاكتمال من ثقة OCR أو من قيمة `complete` يقدمها المستهلك.
- `register_reference_dataset(...)` يتطلب `reference.write` أو صلاحية Super Admin القائمة، ومصدرًا كاملًا بلا حجر، وعددًا مطابقًا للمصدر والـmanifest، ومواقع صفوف مؤهلة وثقة استخراج 100. يسمح التسجيل بالمسودة فقط.
- `approve_reference_dataset(..., reason_code="source_scope_complete")` يتطلب المستخدم النشط من المؤسسة نفسها ودور `super_admin` وصلاحية `workspace.super_admin` الفعليين في قاعدة البيانات. الاعتماد تصديق بشري على النطاق والفترة المحددين، وليس إثباتًا لاكتمال جميع البيانات في العالم.
- الاعتماد المتكرر يعيد الحدث نفسه. تعارض الفترات لنفس مفتاح المرجع محجوب، مع قفل PostgreSQL ثابت على المؤسسة والعائلة والمفتاح. يحمي القيد الفريد الإصدار، وتحمي ORM ومشغّلات PostgreSQL النسخة المعتمدة من التعديل والحذف.
- `applicable_reference_snapshots` القائمة ترجع الشهادات الست نفسها. تضيف الشهادة المعتمدة `dataset_id`, `scope`, `coverage_from/until`, `approval_event_id`, `source_fingerprint` و`records[{source_record_id,record_key,locator,values}]`. تبقى التواريخ ISO والأرقام المالية سلاسل عشرية، دون كائنات Python غير قابلة لحفظ JSON.
- اختيار النسخة يتم بتاريخ الخدمة وفترة تغطية المصدر. وجود نسخة أحدث لا يستبدل المرجع التاريخي. أي عبث بالمصدر أو العدد أو الموافقة يفقد الشهادة أهلية الاكتمال.

نطاق المطالبة يدعم رموز مقدم الخدمة والخدمة والمستفيد، أو أعلام `all_providers/all_services/all_beneficiaries=True` الصريحة. لا تُقبل أعلام شاملة بقيمة false. لا يُقبل `category_code` كشرط نطاق لأن المطالبة لا تحمل فئة موثوقة مباشرة؛ الفئة موثقة داخل صف المستفيد ويطابقها G5 مع الصفوف الأخرى.

## حقول الصفوف الحرجة

كل صف يحمل `effective_from/effective_until`، ورموزًا منظمة فقط بدل النصوص الحرة. المصدر وموقع الصف يغطيان قيم الصف كلها.

| العائلة | الحقول الوظيفية المطلوبة |
|---|---|
| المستفيد | المستفيد والموظف والعلاقة والفئة والخدمات والأهلية الصريحة |
| العقد | مقدم الخدمة ومفتاح العقد والخدمات المشمولة والمستثناة |
| التعرفة | مقدم الخدمة والخدمة والفئة والعملة والوحدة وسعر الوحدة و`price_basis=unit_price` و`price_comparison=exact/ceiling` من المصدر |
| السياسة | الخدمة والفئة والعملة والتحمل وأساسه وطريقة التقريب ودقته واشتراط دليل التنفيذ وسياسة منع تكرار المطالبة المدفوعة وفاصل الصرف الصريح القابل للغياب |
| السقوف | المستفيد والفئة والخدمة والعملة والسقف والاستهلاك وفترته و`consumption_as_of` و`consumed_excludes_current_claim` وأساس الاستهلاك الصريح |
| التاريخ | المستفيد ومقدم الخدمة والخدمة وتاريخها ومرجع المطالبة وحالة الدفع والكمية والوحدة والمبلغ والعملة؛ تاريخ استحقاق الصرف التالي اختياري صريح |

يتحقق G3 من وقوع تاريخ ملخص الاستهلاك داخل فترة المصدر. على G5 التحقق من صلاحيته بالنسبة لتاريخ الخدمة واستبعاد المطالبة الحالية وعدم جمع الملخص والسجل مرة أخرى. لا يفترض القارئ سقفًا للسعر أو فترة شهرية للصرف أو وحدة أو مبلغًا مفقودًا.

حالات الفشل تستعمل القيم القائمة فقط: `reference_missing`, `reference_unapproved`, `reference_not_effective`, `reference_conflict`, `reference_incomplete`, `source_hash_invalid`. لا يمكن اعتبار نقص المرجع أو العبث به دليل مخالفة. يظل مسار المرجعيات القديم وحواجز الاعتماد المالي كما هما.
