# سجل استئناف التنفيذ — الواجهات والمدخلات والصلاحيات

## حدود الإذن

تنفيذ الاتفاقات الأخيرة واختبارها، مع بيانات اصطناعية لجميع المدخلات.
تطوير الوكلاء وOCR مؤجل. لا Commit أو Push أو Merge أو نشر ضمن الإذن الحالي.
البيانات الحقيقية وملفاتها ومفاتيحها لا تُستبدل أو تُحذف.

## النسخة المرجعية ونقطة الاستئناف

- `node_modules` رابط غير متتبع موجود قبل المهمة، لا يُضاف إلى التسليم.

## الاتفاقات التي يجب المحافظة عليها

1. خمسة أقسام: الرئيسية، المدخلات، التدقيق والمراجعة، التقارير، الإدارة.
2. رفع Excel المطالبات والفواتير داخل التدقيق، وليس ضمن أشجار المدخلات.
3. صفحات المدخلات جداول؛ أزرار الإضافة والتعديل أسفل الصفحة. العقود وبقية
   المراجع ذات البنود تدعم إضافة أصل وإضافة بند وتعديل بند محدد.
4. صلاحيات غير السوبر أدمن مجمدة افتراضيًا، بما فيها مدير الجهة. الإضافة
   والتعديل مستقلان لكل مدخل، ويمنحهما السوبر أدمن بعد إجراءاته الخارجية.
5. التحقق على الخادم والعزل وسجل المنح والسحب مستمرون. الإدارة التقنية لا
   تحصل على اعتماد مالي تلقائيًا.
6. أصل المطالبات محفوظ دون تعديل. أربعة ملفات حصرية على مستوى بند الخدمة:
   مقبول مبدئيًا، مرفوض مبدئيًا، معلق، يحتاج مراجعة. لا ملف شامل مكرر.
7. المطلوب قبل التحمل، الصافي بعده وأساس مبلغ المطالبة؛ لا خصم ثانٍ للتحمل.
8. التسعيرة خاصة بالمقدم وبتاريخ الخدمة. الأدوية وبعض الفحوصات تعتمد الفاتورة
   عند غياب تسعيرة فقط؛ غياب تسعيرة بقية الخدمات يعلّق البند للمراجعة.

## الحالة عند استئناف العمل

هذا جدول نقطة البداية فقط؛ الحالة الأحدث في قسم «التنفيذ المحفوظ» أدناه.

| الجزء | الحالة المثبتة |
|---|---|
| آخر عملية مكتملة | فحص Git وشجرة الملفات ومراجعة التعديلات الموجودة وفحص استيراد التطبيق |
| صلاحيات السوبر أدمن | مسودة خدمة/API محفوظة؛ الاختبارات الوظيفية لم تكتمل بعد |
| استبدال المراجع الذري | مسودة endpoint وخدمة وحقول البنود محفوظة؛ تحتاج الاختبار |
| الواجهات الخمس وجداول المدخلات | لم تُعدّل بعد عند هذه النقطة |
| المخرجات الأربعة | لم تُنفذ بعد عند هذه النقطة |
| البيانات الاصطناعية الشاملة | مأذون بها؛ لم تُجهز بعد عند هذه النقطة |
| اختبارات المسار والمتصفح | لم تُشغّل بعد على التعديلات |
| CI | نتائج GitHub السابقة تخص commit منشورًا فقط، لا التعديلات المحلية |

## التحقق الفعلي

- `git diff --check`: نجح عند الاستئناف.
- استيراد `mcias.app`: نجح (`IMPORT_OK`).
- لم يُسجل نجاح pytest أو المتصفح أو PostgreSQL على المسودات حتى هذه النقطة.

يُحدّث هذا السجل بعد كل تحقق بنتيجته الفعلية، مع حفظ التفاصيل خارج أي ملف
أسرار أو بيانات طبية. لا تعني حالة وجود الكود جاهزية إنتاجية أو قبولًا مؤسسيًا.

## الأعمال المتبقية وحدود التحقق

1. **الوكلاء وOCR والتنفيذ المالي الكامل**: مؤجلة حسب الاتفاق. زر تنفيذ مالي
   صوري غير موجود؛ شاشة التدقيق توضح الحد. البند بلا لقطة تدقيق يوضع معلقًا
   وغير مدقق. اللقطات القديمة دون أساس NET المؤكد تذهب للمراجعة.
2. **نشر المراجع المالية**: المدخلات الجديدة مقترحات لا تنشّط قواعد الأسعار
   والسقوف والتحمل تلقائيًا. يلزم مسار اعتماد وربط محرك وفق البيانات الحقيقية.
3. **PostgreSQL وDocker وWindows**: لم تُشغّل اختبارات النسخة الجديدة عليها هنا.
   نجاح لابتوب المالك السابق وCI التاريخي لا يثبت نجاح هذه التعديلات.
4. **CI القديم**: `scripts/check_institution_browser.py` ما زال يفترض سبعة أقسام
   وبطاقات ومنح فئات قديمة. `scripts/check_reference_intake_browser.py` ما زال
   يفترض بطاقات وزر استيراد داخل المدخلات. هذه توقعات تغيرت وظيفيًا. لم تُشغّل
   هذه السكربتات أو Actions، ولم تُحذف لتجميل النتائج؛ تحتاج مطابقة مع الواجهة
   الحالية في قاعدة PostgreSQL معزولة قبل إعلان CI جاهزًا.
5. عرض بنود المطالبات/النتائج في drawer يقتصر على أول 100 مع تنبيه؛ التصدير
   يشمل كامل الدفعة حتى حد 10,000 بند. لا يدعم هذا التعديل أحمالًا أكبر.
6. أسماء الخدمات الملتبسة، بدائل الفاتورة، اختيار المرجع الفعال والتحمل بحسب
   الفئة والشبكة: قرارات محفوظة، لكن تكاملها المالي الكامل ليس مثبتًا بهذا العمل.
7. لا Commit أو Push أو Merge أو نشر، ولا تغيير لترحيل سابق أو تطوير للوكلاء.

  الإصدار بحسب تاريخ الخدمة دون إلغاء المرجع الحالي بسبب إصدار مستقبلي، ودون
  إعادة تنشيط إصدار قديم بعد انتهاء بديله.
