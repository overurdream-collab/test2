# خطة اختبار اللابتوب الموحدة

معرّف الوثيقة: `MCIAS-LAP-002` · الإصدار: 1.0 · التاريخ: 2026-10-11 · الحالة: خطة جاهزة للمراجعة؛ التنفيذ على الجهاز NOT_EXECUTED

[English](LAPTOP_TEST_PLAN_EN.md) · [Runbook](LAPTOP_RUNBOOK.md) · [قائمة التحقق](LAPTOP_TEST_CHECKLIST.md) · [التقرير](LAPTOP_TEST_REPORT.md)

## الهدف والنطاق

التحقق من تشغيل نفس مشروع MCIAS من فرع `feat/windows-laptop-testing` على Windows 11 بذاكرة 8 GB وDocker Desktop/WSL2، قبل اتخاذ قرار دمج PR #17. لا يشترط الدمج لبدء التجربة. ثبّت SHA كاملاً طوال الجولة؛ أي تغيير للمصدر يفتح جولة جديدة مع إعادة الاختبارات المتأثرة وتوثيق الباقي.

الموافقة الحالية تخص إعداد هذه الوثائق فقط. قبل التنفيذ يسجل المستخدم موافقته على نطاق التجربة، بما يشمل بناء الصور، وتهيئة قاعدة اختبار جديدة، وتوليد مفاتيح وحسابات، والمصادقة وإدخال بيانات اصطناعية والإيقاف وإعادة التشغيل. تغيير الكود، أو إضافة ملفات بيانات جديدة، أو تشغيل اختبارات إضافية، أو رفع الفرع وتشغيل CI، أو الدمج يحتاج موافقة تغطي ذلك الإجراء. لا تشغّل الأوامر بمجرد وجودها في الوثائق.

المرجع الملزم هو [عقد القبول](ACCEPTANCE_CONTRACT.md)؛ حالة [البوابات](../GATE_STATUS.md) تبقى OPEN / NOT_ACCEPTED. هذه تجربة لحزمة اللابتوب، وليست UAT مؤسسياً أو تفويض معالجة بيانات حقيقية. راجع [تغطية الواجهات](FRONTEND_ROUTE_API_MATRIX.md) و[الخطة الخارجية](EXTERNAL_TEST_PLAN.md) للمتطلبات الأوسع.

## شروط البدء

- المشغّل والمراجع وموافقة التنفيذ والنطاق مسجلون في التقرير.
- Windows 11 و8 GB RAM، وGit وDocker Desktop بوضع Linux containers/WSL2 جاهزة؛ إصداراتها الفعلية مسجلة.
- نسخة Git نظيفة ومثبتة عند SHA مراجع، على NTFS محلي خارج OneDrive والمجلدات المشتركة.
- قاعدة `mcias_laptop_e2e` وvolumes لهذا الاختبار فقط. عند اكتشاف تثبيت قائم، تُراجع بياناته ومفاتيحه قبل Start؛ لا reset ولا حذف volumes.
- الوقت التلقائي للهاتف وWindows، ومصادقة TOTP، ومتصفح حديث، ومساحة قرص متاحة ومسجلة.
- تستخدم الملفات الاصطناعية الموجودة والموافق عليها فقط. لا بيانات مرضى أو عقود حقيقية. توليد ملف إضافي يحتاج موافقة.
- ماسح الملفات معطل في هذه الحزمة؛ لا دليل على فحص malware أو جودة OCR منها.

## الأدوار والبيانات

المشغّل ينفّذ نطاقاً مصرحاً ويجمع الأدلة؛ المراجع يتحقق من النتائج؛ المستخدم يقرر رفع الفرع أو الدمج بصورة منفصلة. حساب `SYN-laptop-admin` للإعداد التجريبي، و`SYN-laptop-reviewer` للمراجعة المستقلة، والقارئ محدود الصلاحيات. لقب super_admin لا يتجاوز RBAC أو الفصل بين الأدوار.

أول تهيئة جديدة تولّد 12 مطالبة اصطناعية، قيمة كل منها 1,000 LYD، وتقريرها يحتجزها جميعاً دون استحقاق مالي معتمد. لا تخلطها مع `demo.json` الذي يعرض نتائج ثابتة اصطناعية منفصلة. المسار الاختياري `--verify-inputs` يضيف عقد مسودة وتسعيرة وفئة وانتساباً ومطالبة 100 LYD؛ يحتاج موافقة إدخال ويغيّر العدّ المتوقع إلى 13 في تشغيله الأول على قاعدة جديدة. تكراره يضيف بيانات أخرى؛ لا يعتبر إعادة تشغيل للقراءة فقط.

## التنفيذ والنتائج

الترتيب: موافقة وسجل البيئة → تهيئة → صحة ومصادقة → واجهات → مدخلات اصطناعية → تقارير → استمرارية → موارد → مراجعة التقرير. يُنفّذ السيناريو مرة، وتوثّق كل إعادة وسببها. السيناريو ذو شروط سابقة ناقصة يكون BLOCKED، لا PASS.

الحالات: `NOT_EXECUTED` لم ينفذ؛ `PASS` تحقق المتوقع بدليل؛ `FAIL` نُفذ وخالف المتوقع؛ `BLOCKED` منع نقص صلاحية/بيئة/قدرة تنفيذه؛ `OUT_OF_SCOPE` خارج الجولة المحددة. لا تجمع نتائج CI واللابتوب ولا الاختبارات المتداخلة كعدد نجاح واحد. سجل التحذيرات وskipped وبيانات demo منفصلة.

## شروط التوقف والقرار

توقف عند ظهور بيانات حقيقية، أو كشف سر، أو تجاوز صلاحية، أو تعديل أصل/لقطة، أو فقد بيانات، أو تعطل متكرر/OOM. احفظ دليلاً منقحاً، ولا تحذف أو تصلح أو تعيد توليد مفاتيح دون موافقة جديدة. تصنّف الخصوصية/الصلاحيات/سلامة البيانات كمشكلات مانعة للتوصية بالدمج.

التوصية بدمج حزمة اللابتوب تتطلب PASS موثقاً لكل LAP-01 إلى LAP-20 على نفس النسخة، وإغلاق العيوب المانعة، وتوثيق LAP-21 إلى LAP-24 خارج النطاق، ومراجعة بشرية. أي FAIL/BLOCKED/NOT_EXECUTED أساسي يبقي القرار HOLD. التوصية لا تنفذ الدمج؛ يحتاج موافقة المستخدم ومراجعة CI للنسخة النهائية. القبول المؤسسي منفصل.
