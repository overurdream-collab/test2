# تسليم نظام الميزات وواجهة المدخلات — MCIAS

تاريخ التحقق المحلي: 2026-10-12. المستودع: `overurdream-collab/test2`، الفرع: `feat/windows-laptop-testing`. الأصل المرجعي على GitHub: `8f5eea76fc324089b6649031150790345a0d9c01`.

## النطاق المنفذ

اكتملت ست مراحل متتابعة: نماذج وخدمات وAPI الميزات؛ شاشة الإدارة المركزية؛ القائمة حسب الاستحقاق والصلاحية؛ خلفية المدخلات المشفرة؛ شجرة الواجهة؛ والتحقق النهائي والتشغيل والتوثيق. لم تُعدل نماذج RBAC التاريخية أو خدماته أو مساراته، أو أي Migration سابق، أو أي ملف اختبار موجود قبل هذه المهمة. لم يُنشأ فرع آخر ولم يُدمج main. أضيف استيراد نماذج الميزات إلى `alembic/env.py` فقط، دون تغيير سلسلة الترحيل. رأس قاعدة البيانات يظل `0021_organization_features`.

الكتالوج الفعلي 44 ميزة: 11 حاوية و33 ورقة. الحاويات تجمع الأوراق في العرض؛ لا يُقبل منحها مباشرة. لا يمنح الإعداد أي ميزة لأي جهة تلقائياً، ولا أضيف Seed تشغيلي. هويات ومدخلات المتصفح اصطناعية صريحة في قواعد اختبارات معزولة فقط.

## المعمارية والأمان

- `mcias/models_features.py` يطابق جدولَي 0021 وقيودهما. المنح والسحب بتاريخ ونسخ؛ لا DELETE.
- `mcias/services/feature_service.py` يعمل بـ flush دون commit ويُسجل AuditLog في المعاملة. أقفال PostgreSQL تمنع تنافس التحديثات؛ النسخة المتوقعة في الحفظ الجماعي تمنع الكتابة فوق تعديل آخر. الحفظ الجماعي ذري ويحتاج سبباً للسحب.
- `mcias/api/features_routes.py` يقدم الكتالوج والمنح والسحب وحالة المستخدم. توثيق Super Admin يستخدم دور `super_admin` الموجود وMFA مفعلاً ومستخدمًا ساريًا، ولا يعتمد على `is_super_admin` وحده. هذا استثناء تأسيسي ضيق للحوكمة التقنية، لأن الصلاحيات النظامية ليست قابلة لمنحها لمجموعات الجهات في RBAC الحالي. لا يوسع صلاحيات القراءة الطبية أو القرار المالي.
- ظهور صفحة جهة يتطلب استحقاق الميزة **وصلاحية القراءة**. الميزات لا تمنح صلاحيات RBAC. السحب يمنع طلبات API الجديدة؛ زر التحديث يعيد بناء القائمة. لا يمحو السحب معلومات سبق قراءتها في جهاز المستخدم بأثر رجعي.
- `mcias/middleware/features.py` يحمي مجموعات المسارات القديمة المدونة فيه. يعمل تلقائياً في production، وفي development عند `MCIAS_FEATURE_ENFORCEMENT=true`. البنية الأساسية للاستيعاب تحت RBAC القديم؛ لا توجد ورقة ingestion في الكتالوج الحالي. مسارات الميزات والمدخلات الجديدة تفرض الحماية دائماً، بصرف النظر عن متغير ترحيل المسارات القديمة.
- `mcias/api/feature_data_routes.py` يوفر إسقاطات قراءة محدودة ومعزولة بالجهة لمواءمة RBAC الزمني مع قوائم المطالبات والدفعات والعقود والتدقيق والحالات والمستخدمين، دون تعديل API القديم.
- جميع الردود المحمية الجديدة no-store؛ الرموز في ذاكرة الواجهة فقط؛ لا تخزين جلسات في localStorage/sessionStorage؛ نصوص الخادم تُعرض بوسائل DOM الآمنة. الأخطاء والمدخلات الحساسة لا تُعاد في رسائل التحقق.

## المدخلات ليست تفعيل سياسة مالية

`registry_service.py` يقدم **سجلاً مرجعياً مقترحاً مشفراً ومؤرخاً** للأقسام الستة عشر. يستعمل SourceFile وEncryptedStore الحاليين، وAuditLog كفهرس أحداث append-only، دون إضافة جدول أو Migration أو تعديل محرك الحساب. تحفظ الأسماء والقيم والأسباب في محتوى مشفر؛ سجل التدقيق يحمل معرفات ونسخاً وهاشات وإشارات مصدر فقط.

الإضافة والإغلاق وإعادة الإصدار والاستيراد تعمل فعلياً. كل سجل يعرض `approval_status=pending_institutional_review` و`financially_active=false`. **لا يُحوَّل تلقائياً إلى ProviderContract أو BeneficiaryEnrollment أو ProviderTariff أو سياسة G5 معتمدة**. إدخال عقد أو سقف في هذه الواجهة لا يغير المدفوع المستحق. الربط المؤسسي واعتماد البيانات المعيارية يبقيان ضمن دورة G3/G5 الموجودة وما يلزم لها من تفويض. هذا حد تنفيذي مقصود للحفاظ على قواعد الموافقة والفصل بين المسؤوليات.

الإغلاق حدث جديد؛ التاريخ السابق ثابت. إنشاء سجل = النسخة 1، إغلاقه = النسخة 2، إعادة إصداره = النسخة 3. لا زر حذف. لا تعديل مباشر للسجل المغلق. التعارض يرجع 409.

الاستيراد يدعم CSV/XLSX/PDF حقيقية عبر الاستيعاب الحالي. تبدأ العملية برفع المصدر، ثم استخراج أو حجر، ومعاينة والتحقق، وتحديد السجلات وتأكيد بشري، وحفظ مع ربط الأصل وSHA-256. PDF يحتاج تعبئة بشرية للحقول؛ استخراج النص ليس تفسيراً تلقائياً للعقود. تنزيل الأصل يقتصر على دليل مرتبط بسجل مسموح في الجهة نفسها.

حدود الإصدار: الملف 20 MiB، المعاينة والدفعة حتى 100 صف، وفهرس المدخلات حتى 10,000 حدث لكل جهة وقسم، مع رفض صريح عند تجاوز الحد. البحث والقوائم تفك تشفير السجلات المسموح بها؛ هذا حل مدخلات محدود السعة، وليس مخزن تحليلات واسع النطاق. الملفات المشفرة التي تكتب قبل تراجع معاملة قد تحتاج مصالحة تشغيلية لاحقة؛ لا توجد مهمة تنظيف جديدة هنا.

## الواجهة

القائمة المؤسسية: الرئيسية ← المدخلات والبيانات ← المطالبات والدفعات ← التدقيق والمراجعة ← التحليلات ← التقارير ← المستخدمون داخل الجهة. يظهر كل عنصر حسب الصلاحية والاستحقاق.

داخل المدخلات والبيانات ثلاثة أشجار:

1. المدخلات: العقود، الآليات واللوائح، الاستثناءات، الموافقات والتفويضات، السقوف، التغطية.
2. المستفيدون: الأسماء، الفئات، المشاركة في التكلفة.
3. مقدمو الخدمة: المستشفيات، العيادات، المختبرات، الأشعة، الصيدليات، الخدمات، التسعيرات.

16 شاشة مؤسسية و16 مساراً مركزياً نظيراً، إضافة لقائمة مستخدمي الجهة وشاشتَي إدارة الميزات: **35 مساراً جديداً، و94 تعريف مسار إجمالاً**. الصفحات المتاحة لها تحميل وفراغ وخطأ ومنع وصول، بحث وتصفية وترقيم، نافذة تفاصيل وتاريخ ودليل، ونماذج إضافة وإغلاق ونسخ ورفع ومعاينة. العرض العربي RTL والإنجليزي LTR، والسمتان الفاتحة والداكنة، وأحجام 1440/768/390 موثقة بالمتصفح. الشاشات القديمة المخططة لا تصبح عاملة بسبب وجودها في القائمة.

## إعداد اللابتوب

من PowerShell في نسخة الفرع:

```powershell
git pull --ff-only origin feat/windows-laptop-testing
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\laptop.ps1 -Action Start
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\laptop.ps1 -Action Check
```

Start يحافظ على المفاتيح والإعداد الحاليين، وينفذ الإعداد الأصلي ثم `python -m mcias.feature_runtime` بحساب المالك. الوحدة تمنح صلاحيات أعمدة إغلاق RBAC والميزات وأعمدة القفل، ولا تمنح ميزات أو مجموعات أو بيانات. لا حاجة لإعادة إنشاء قاعدة البيانات أو حذف بيانات اللابتوب. لا يُفترض أن حساب runtime مالك الجداول أو superuser.

للبيئة غير اللابتوب، بعد الترحيل الحالي وإنشاء الحساب، ينفذ مالك قاعدة البيانات السكربت السابق `deploy/setup_rbac_permissions.sql`، ثم:

```bash
psql "$OWNER_DATABASE_URL" -v runtime_user="$RUNTIME_USER" -f deploy/setup_feature_permissions.sql
```

القيم أعلاه أسماء متغيرات محلية، وليست أسراراً مضمنة. يضاف SELECT للكتالوج والمنح، INSERT للمنح، UPDATE لأعمدة الإغلاق فقط، organizations.name وusers.active لدعم قفل الصفوف. امتلاك UPDATE على هذه الأعمدة قدرة حقيقية على تعديلها؛ Trigger 0019 يحمي السجل المغلق ويمنع الحذف، ولا يمنع كل تغيير للسجل المفتوح. لا تُمنح UPDATE للمفاتيح أو password_hash عبر هذه الإضافة.

بعد الدخول بـSuper Admin، افتح `/admin/features` واختر الجهة، امنح الأوراق المطلوبة واحفظ. مستخدم الجهة يحتاج صلاحيات RBAC المناسبة أيضاً؛ لا استحقاق افتراضي. زر تحديث يقرأ `/api/v1/me/features` من جديد.

## أدلة الاختبار المحلي

| المرحلة | التحقق قبل الانتقال |
|---|---|
| 1 — Models/Services/API | 453 اختبار Python ناجح، وحساب PostgreSQL محدود |
| 2 — إدارة الميزات | 455 ناجح، ومتصفح HTTP/PostgreSQL للحفظ والسحب والإلغاء |
| 3 — Sidebar | 458 ناجح، والمنح/السحب والمنع قبل الطلب |
| 4 — خلفية المدخلات | 484 ناجح في التشغيل الشامل، واختبار حساب مدخلات محدود إضافي ناجح |
| 5 — الأشجار والصفحات | 518 ناجح، و16 صفحة وإغلاق ونسخ واستيراد وتنزيل في Chromium |
| 6 — التحقق النهائي | 520 Python ناجح / 0 فاشل / 0 متجاوز؛ 17 JavaScript ناجح / 0 فاشل |

نجح بناء Wheel وفحص احتوائه على جميع وحدات الميزات والمدخلات وأصول JavaScript الجديدة.

الفحص الشامل استخدم ثلاث قواعد PostgreSQL معزولة للاختبارات العامة وAPI وSeed، ولم يعتمد على تجاوز اختبارات PostgreSQL. ظهرت 21 رسالة تحذير إهمال من Starlette TestClient وتهيئة Alembic؛ ليست إخفاقات. نجح فحص حالات المسارات الـ94، والمتصفح الجديد الثلاثي، والدورة القديمة للاستيعاب/التدقيق/المراجعة/التقارير، والاحتفاظ، والدخول والقراءة والخروج. تقارير المتصفح المرفقة تصرح بأنها اصطناعية. لم تظهر أخطاء JavaScript أو مخالفات axe في المشاهد التي فُحصت؛ هذا لا يعادل تدقيق وصول شامل لكل حالات المنتج.

CI يشغل الاختبارات المجمعة على قواعد PostgreSQL مخصصة، ويختبر الميزات الجديدة عبر `scripts/check_feature_system.py`، مع تفعيل حارس الميزات للمسارات القديمة في مرحلة المتصفح. سجلات CI على Commit المنشور هي المرجع لحالة GitHub؛ الأعداد هنا نتائج محلية محفوظة، وليست ادعاء قبول إنتاجي.

## إعادة التحقق

```bash
python -m pytest tests/ -v
node --test --test-isolation=none tests/frontend/*.test.mjs
npm run check
python scripts/check_feature_system.py --base-url http://127.0.0.1:8000
python -m pip wheel . --no-deps -w dist
```

تشغيل PostgreSQL يحتاج MCIAS_TEST_DATABASE_URL وMCIAS_RBAC_API_DATABASE_URL وMCIAS_SEED_TEST_DATABASE_URL لقواعد اختبار منفصلة. يتطلب فحص المتصفح تطويراً صريحاً وقاعدة *_e2e وMCIAS_E2E_DATABASE_URL ومفتاح MFA الموجود في خادم الاختبار وChromium وaxe-core. الإجراء يحضر هويات اختبار صريحة فقط؛ بياناتها الخاصة تبقى في ملف مؤقت محدود الصلاحيات ولا تدخل التقرير أو artifacts.
