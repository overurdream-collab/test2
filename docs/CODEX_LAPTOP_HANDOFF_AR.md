# تسليم MCIAS إلى Codex على اللابتوب

## النسخة ومصدر الحقيقة

- المستودع: https://github.com/overurdream-collab/test2
- الفرع: `feat/windows-laptop-testing`؛ لا تنتقل إلى `main` ولا تدمج تلقائيًا.
- أساس هذا التسليم المنشور: `86376d44af9b29e6d52c7eed3d596c6530257a0a`. تتضمن النسخة التي تحتوي هذا الملف تعديلات واجهة مدير الجهة اللاحقة له.
- ثبّت رقم نسختك الفعلي عند البداية باستخدام `git rev-parse HEAD`. لا تنسب نتائج CI لنسخة مختلفة.
- طلب المراجعة الحالي: https://github.com/overurdream-collab/test2/pull/17
- آخر ترحيل في هذه النسخة: `0023_insurer_intake`، بعد `0022_rbac_authority`.

هذه حزمة مصدر وسياق. لا تنقل قاعدة البيانات السحابية أو مفاتيحها أو كلمات المرور إلى اللابتوب. بيانات اللابتوب الحالية تبقى في مجلد الإعداد الخاص وDocker volumes الخاصة به.

## الأوامر على Windows

إذا كان المشروع موجودًا بالفعل في `F:\MCIAS\test2`، افتح PowerShell:

```powershell
Set-Location F:\MCIAS\test2
git status --short
```

إذا ظهرت تعديلات محلية، توقف واعرض أسماء الملفات للمراجعة؛ لا تستخدم `reset --hard` أو `clean` أو حذف البيانات. إذا كانت النسخة نظيفة:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\laptop.ps1 -Action Stop
git switch feat/windows-laptop-testing
if ($LASTEXITCODE -ne 0) { throw 'تعذر اختيار الفرع؛ توقف' }
git pull --ff-only origin feat/windows-laptop-testing
if ($LASTEXITCODE -ne 0) { throw 'تعذر تحديث المصدر؛ توقف' }
git rev-parse HEAD
```

إذا لم توجد نسخة محلية، استخدم مجلدًا جديدًا:

```powershell
git clone --branch feat/windows-laptop-testing --single-branch https://github.com/overurdream-collab/test2.git F:\MCIAS\test2
Set-Location F:\MCIAS\test2
git rev-parse HEAD
```

افتح **المجلد نفسه** في تطبيق Codex على اللابتوب. إذا كنت تستخدم Codex CLI المثبت لديك:

```powershell
Set-Location F:\MCIAS\test2
codex
```

عدم وجود أمر `codex` لا يستلزم إعادة نسخ المشروع؛ افتح المجلد في تطبيق Codex أو ثبّت العميل المناسب من المصدر الرسمي بصورة مستقلة. لا تمنح موافقة تلقائية على كل الأوامر.

لتشغيل النسخة بعد تحديث المصدر، بصورة مستقلة عن فتح Codex:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\laptop.ps1 -Action Start
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\laptop.ps1 -Action Check
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\laptop.ps1 -Action Credentials
```

ابدأ الاختبار في http://127.0.0.1:8000/institution/dashboard أو المنفذ المحفوظ في إعدادك. لا تغيّر مفاتيح التشفير، ولا تحذف Docker volumes، ولا تشارك مخرجات Credentials.

## الهدف المعتمد

MCIAS منصة داخلية لتدقيق المطالبات الطبية مع PostgreSQL وFastAPI وSQLAlchemy وAlembic، وواجهة Vanilla JavaScript عربية RTL وإنجليزية LTR، بوضعين فاتح وداكن.

المطلوب الحالي المكتوب من المالك: واجهة مدير الجهة بهذا الترتيب فقط:

1. الرئيسية.
2. المدخلات والبيانات.
3. المطالبات والدفعات.
4. التدقيق والمراجعة.
5. التحليلات.
6. التقارير.
7. مستخدمو الجهة.

الرئيسية تعرض عدد المستفيدين، **شركات التأمين تحديدًا**، مقدمي الخدمات، مستخدمي الجهة، وصحة النظام. لا تعد مقدمي الخدمات شركات تأمين. المؤشرات من بيانات الجهة المسموح بها، لا أرقام تجميلية أو بيانات عرض مخفية.

## ما تتضمنه هذه النسخة

| المجال | التنفيذ والمصدر |
|---|---|
| لوحة مدير الجهة | `mcias/web_workspace/institution.js` و`mcias/services/institution_workspace.py` |
| قائمة مرتبة من سبعة أقسام | `mcias/web_workspace/feature_navigation.js` و`app.js` |
| دليل الموظفين وإدارة حساباتهم | شاشة `/institution/users`، مع استخدام خدمات وAPI RBAC الحالية للإنشاء والإسناد والسحب والإغلاق |
| API قراءات الجهة | `mcias/api/institution_routes.py`: overview، users، assignment-groups |
| إدخال شركات التأمين وعقودها | `inputs.insurers` في `mcias/schemas/registry.py`، ومسار `/institution/inputs/insurers` |
| كتالوج الميزات | 45 ميزة: 11 حاوية و34 ورقة؛ إضافة واحدة في `0023_insurer_intake`؛ دون منح بيانات جهات في الترحيل |
| حساب مدير جهة اختباري | `mcias/seed/institution.py` مع `mcias/seed/laptop.py`، محصور بقاعدة اختبار اللابتوب |
| اختبارات الوظائف الجديدة | `tests/features/test_institution_workspace.py` و`scripts/check_institution_browser.py` |

هذه النسخة لا تثبت اكتمال كل الواجهات المركزية أو دورة مالية مؤسسية. تفاصيل المؤشرات وحدودها في [INSTITUTION_ADMIN_WORKSPACE.md](INSTITUTION_ADMIN_WORKSPACE.md).

## الحسابات والصلاحيات

- `SYN-laptop-admin`: حساب الإدارة التقنية الاختباري الموجود سابقًا.
- `SYN-laptop-reviewer`: حساب المراجعة الاختباري الموجود سابقًا.
- **`SYN-laptop-institution-admin`**: حساب مدير الجهة الجديد؛ استخدمه لتجربة الواجهة المطلوبة. كلمة المرور وTOTP عشوائيان ويعرضهما أمر Credentials محليًا.
- الحسابات القديمة وكلمات مرورها ومفاتيح MFA تبقى عند التحديث. التهيئة المتكررة لا تستعيد منحًا أُلغي لاحقًا.
- لا تمنح الإدارة التقنية اعتمادًا ماليًا نهائيًا تلقائيًا. القرار المالي النهائي يتطلب الموظف المفوض وضوابط الجهة.
- مدير الجهة يدير الموظفين ويسند الفئات الوظيفية المراجعة، ولا يغير صلاحيات الفئات أو يسند فئة لنفسه أو يدير الحسابات التقنية من هذه الشاشة.
- المصدر الوظيفي هو منح الفئات المراجعة والموقعة؛ لا تعِد جمع صلاحيات legacy والمنح الفردية تلقائيًا لتجاوز رفض الوصول.
- الميزات تحدد إتاحة الوحدات؛ صلاحيات Backend تبقى شرطًا مستقلاً. إخفاء الرابط ليس حاجزًا أمنيًا.

## قرارات يجب الحفاظ عليها

1. الحفاظ على Backend وPostgreSQL والعزل بين الجهات؛ لا استبدال التطبيق.
2. لا تعديل migrations السابقة المنشورة. أي تغيير مخطط جديد له ترحيل مستقل وأثر بيانات واضح.
3. لا حذف بيانات أو سجلات تاريخية؛ الإغلاق والإصدارات محفوظة وفق الضوابط الحالية.
4. التاريخ المالي يعتمد تاريخ الخدمة. الإغلاق الإداري وانتهاء السريان مفهومان مختلفان؛ المعالجة الأوسع للتواريخ تحتاج قرارًا وخطة معتمدة.
5. AI استشاري؛ لا قرار مالي أو طبي ملزم آليًا، ولا تحويل الاشتباه إلى خصم تلقائي.
6. موافقات القواعد والعقود والسياسات المالية مستقلة وتحتاج أدلة وتفويضًا وفصل واجبات.
7. لا يكفي وجود اسم وكيل أو وثيقة أو شاشة لإثبات اكتمال الوظيفة.
8. نجاح الاختبارات الاصطناعية لا يساوي اعتماد G1–G9 مؤسسيًا أو UAT أو اختبار اختراق.
9. ممنوع تسجيل كلمات المرور وTOTP وبيانات طبية حساسة في التقارير أو GitHub.

## الأدلة وحدودها

- التشغيل السحابي السابق لهذه التعديلات: 555 اختبار Python ناجح، 18 اختبار JavaScript ناجح، وفحص Chromium عبر HTTP وPostgreSQL يشمل 30 صفحة مدير جهة ودورة موظف كاملة وفحوص RTL/LTR والوضعين وإمكانية الوصول.
- جُرّب تحديث Docker من الحسابين القديمين إلى ثلاثة حسابات، مع حفظ معرفات الحسابات وكلمات المرور وMFA وبيانات الاختبار، وفحوص تشغيل ناجحة.
- هذه أدلة هندسية في بيئة Linux سحابية؛ **ليست نتيجة على جهاز Windows 11 الفعلي**. تحقق من CI للـSHA الذي نسخته؛ لا تفترض أن سجلًا أقدم يثبت النسخة الأحدث.
- اعتماد الجهة، البيانات الحقيقية، القرارات المالية الرسمية، UAT، واختبار الاختراق لا تزال مسارات منفصلة.

## حدود هذه المحادثة والأعمال المفتوحة

هذه الوثيقة تحفظ ما استعيد من السياق المتاح والكود؛ لا تدعي نقل جميع رسائل المحادثات السابقة تلقائيًا. آخر طلب هو نقل العمل إلى Codex على اللابتوب، مع إتمام حفظ واجهة مدير الجهة. لا يوجد إذن جديد بإعادة تصميم النظام المركزي أو إصلاح جميع الفجوات التاريخية دفعة واحدة.

الخطوة التالية: التحقق قراءةً فقط من SHA والفرع ونظافة Git، ثم مراجعة هذه الوثيقة والواجهة. تشغيل النسخة واختبارها على Windows يتم بالأوامر أعلاه؛ قبل أي تطوير جديد، قدم النطاق والسبب وخطة الاختبار واطلب موافقة صريحة.

لا تنفذ من تلقاء نفسك مراحل معالجة القواعد أو سجل الأسرة أو إعادة التقديم أو الأعمدة التحليلية الخمسة عشر؛ بعض تفاصيلها لم تعتمد بعد. لا تعتبر أرقام migrations المقترحة تاريخيًا خطة نافذة.
