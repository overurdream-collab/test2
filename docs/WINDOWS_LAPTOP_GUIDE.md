# تشغيل MCIAS على Windows 11 وذاكرة 8 GB

معرّف الوثيقة: `MCIAS-LAP-001` · الإصدار: 1.0 · الحالة: حزمة اختبار اصطناعي محلي؛ ليست اعتماد إنتاج

[English](WINDOWS_LAPTOP_GUIDE_EN.md) · [متطلبات الجهة](policies/CLIENT_REQUIREMENTS.md) · [خطة الاختبار الخارجية](EXTERNAL_TEST_PLAN.md)

## ما تشغله هذه الحزمة

حاويتان دائمتان فقط: PostgreSQL 16 (حد 384 MiB) والتطبيق Python 3.12 (عامل واحد وحد 768 MiB). حاوية setup مؤقتة لها حد 768 MiB للترحيل والإعداد. لا Redis ولا Node ولا متصفح آلي ولا ClamAV/OCR daemon ضمن هذه الحزمة. حدود الحاويات ليست قياسًا لاستهلاك Windows/Docker ولا SLA؛ يلزم رصد الأداء على جهازك.

الوصول `127.0.0.1` فقط عبر HTTP في وضع development وبيانات اصطناعية. قاعدة `mcias_laptop_e2e` وتخزين جديدان؛ التطبيق يستخدم حساب DB محدودًا مختلفًا عن حساب الترحيل. ماسح البرمجيات الخبيثة معطل صراحة في هذا الوضع؛ لا تدخل ملفات عقود أو أسماء أو سجلات حقيقية قبل تجهيز بيئة مصرح بها ومفاتيح وصلاحيات وTLS وماسح محلي وسياسات معتمدة. لا تعرض منفذ التطبيق على الشبكة.

## 1. إعداد Docker Desktop

- Windows 11 مع virtualization وWSL2 وDocker Desktop في وضع **Linux containers**. افتح Docker Desktop وانتظر Ready.
- Git مثبت. لا يلزم Python أو Node على Windows لهذه التجربة الأساسية.
- ضع المشروع خارج OneDrive والمجلدات المتزامنة/المشتركة، مثل `C:\MCIAS\test2`؛ يوصى بقرص NTFS محلي ومساحة كافية للصور والبيانات.
- أغلق البرامج الثقيلة. نقطة بداية مناسبة لتجربة صغيرة: Docker/WSL عند 4 GB و2 CPU، مع بقية الذاكرة لـWindows؛ ليست ضمانًا لكفاية الجهاز تحت كل حمل.
- إن لزم تحديد ذاكرة WSL2، راجع إعدادات Docker/WSL. عند استخدام `%UserProfile%\.wslconfig` ادمج هذه القيم مع الملف الحالي ولا تستبدله أو توقف توزيعات تعمل دون حفظ عملك:

```ini
[wsl2]
memory=4GB
processors=2
swap=2GB
```

تنطبق إعدادات WSL على توزيعات أخرى أيضًا. تطبيقها قد يحتاج إعادة تشغيل WSL/Docker؛ لا تغير الأداة هذا الملف أو سياسة PowerShell العامة تلقائيًا.

## 2. نقل المصدر المراجع

من PowerShell، في مجلد تريد وضع المشروع داخله:

```powershell
git clone --branch feat/windows-laptop-testing https://github.com/overurdream-collab/test2.git
cd test2
git rev-parse HEAD
```

هذا فرع حزمة التشغيل للمراجعة. بعد دمجها يمكن استخدام main وتثبيت SHA كامل تمت مراجعته. لا تنقل `.env` أو `deploy/laptop-private` أو مفاتيح/بيانات الجهاز السابق. الحزمة تحتاج الإنترنت أول مرة لتنزيل الصور والمكتبات؛ البناء يستخدم TLS موثقًا، دون insecure أو تعطيل التحقق.

## 3. بدء التشغيل

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\laptop.ps1 -Action Start
```

Bypass هنا لهذه العملية فقط؛ لا يغير سياسة الجهاز. اقرأ السكربت قبل تشغيله، ولا تستخدمه لتشغيل شيفرة غير موثوقة.

الأداة تولد كلمات مرور DB ومفتاحي المصدر/MFA عشوائيًا، وتحفظها في `deploy/laptop-private/.env` المحمي بـNTFS ACL للمستخدم الحالي وSYSTEM وAdministrators. يمنع junction/symlink للملف/المجلد. الملف مستبعد من Git ومن build context؛ لا تستعمل `docker compose config` دون `--quiet` في تقرير لأنه يكشف القيم المستبدلة.

ثم تبني الصورة، وتجهز قاعدة جديدة وترحيلات head، وتحمّل 12 مطالبة اصطناعية كلها held، وتجهز حسابي إدارة ومراجعة مستقلين مع MFA، وتمنح دور التطبيق أقل صلاحيات هذا السيناريو، وتشغل API وتفحصها. لا توافق على سياسة مالية ولا تنشئ لقطة G5 إنتاجية. إعادة Start تحافظ على كلمات المرور والمفاتيح والبيانات؛ لا تعمل reset.

بعد النجاح افتح:

- `http://127.0.0.1:8000/institution/dashboard`
- `http://127.0.0.1:8000/admin/dashboard`

إذا 8000 مستخدم، اختر قبل أول تشغيل:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\laptop.ps1 -Action Start -Port 8010
```

المنفذ يُحفظ عند التهيئة الأولى. تغييره لاحقًا يحتاج تعديل LAPTOP_HTTP_PORT فقط في الملف المحلي ثم إعادة التشغيل، دون تغيير المفاتيح.

## 4. بيانات الدخول وMFA

في طرفية خاصة، دون مشاركة الشاشة أو التسجيل:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\laptop.ps1 -Action Credentials
```

يعرض حساب `SYN-laptop-admin` و`SYN-laptop-reviewer` وكلمات المرور العشوائية وtotp_secret_base32 لكل منهما. أدخل secret يدويًا في تطبيق Authenticator كـTOTP (6 أرقام، 30 ثانية). اضبط وقت الهاتف وWindows تلقائيًا. أدخل كلمة المرور والرمز في login؛ الرمز المستعمل لا يقبل ثانية. لا تشارك بيانات Credentials أو ترفقها في GitHub/التقرير. لا تمنح الحسابين صلاحيات الحقول الطبية أو تنفيذ/اعتماد سياسة مالية إنتاجية.

يوجد قارئ اصطناعي محدود يستخدمه الفحص التلقائي؛ لا يستعمل هذا الحساب أو بياناته في تشغيل حقيقي. محفوظات حسابي الإدارة والمراجعة في Docker volume state، وضع الملف 0600 وليس مجلد Windows مشتركًا.

## 5. اختبارات الجهاز الأساسية

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\laptop.ps1 -Action Status
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\laptop.ps1 -Action Check
```

Check يتحقق من DB role/head والصحة ودخول القارئ وقراءة المطالبات ومنع وصول القارئ لإدارة المستخدمين وخروجه. يكتب أحداث مصادقة اختبار فعلية؛ لا يغير مطالبات أو قواعد مالية، ولا يطبع رموز الجلسات أو كلمات المرور. TEST_CHECKS_PASS لا يعني قبول G0–G9.

تحقق يدويًا أيضًا: العربية RTL والإنجليزية LTR، Light/Dark، القوائم، البحث بالوحدات، عرض المطالبات والتقرير الاصطناعي، حالات الميزات غير المتاحة، الدخول والخروج وفصل حسابي الاختبار. سجل SHA وتاريخ UTC وبيئة Windows/Docker وPASS/FAIL لكل اختبار مع لقطة منقحة، باستخدام [نموذج التقرير](EXTERNAL_TEST_REPORT_TEMPLATE.md).

هذه ليست الحزمة الكاملة لتشغيل pytest/Playwright على نفس قاعدة الاستخدام. الانحدار والاستعادة يحتاجان قواعد جديدة مستقلة وأدوات إضافية وفق خطة الاختبار؛ لا تشغل reset/restore/regression على قاعدة بدأت إدخالها. لا تعد بنجاح كل اختبارات Windows قبل تشغيلها عليه فعليًا.

## 6. ترتيب تجربة المدخلات

1. جهز قائمة مدخلات الجهة وصيغها وحقولها والسياسات دون إدخال سجلات حقيقية الآن.
2. أدخل بيانات عقود وتسعيرات وفئات وأهلية **اصطناعية** صغيرة من /admin/reference-data؛ العقود تبدأ draft، والتفعيل له مراجعة ودليل وصلاحيات.
3. ارفع Excel/CSV/PDF اصطناعيًا من ingestion، وافحص SHA والـmanifest والعزل، ثم دفعة المطالبات واستئنافها وربط المرفقات.
4. افحص تقارير held ورفض العمليات غير المفوضة؛ لا يعتبر verified موافقة بشرية أو دفعًا.
5. اربط كل متطلب فعلي بواجهة/API/جدول وسياسة؛ استكمل الغائب قبل تجربة مؤسسية كاملة.

| المدخل | الحد الحالي |
|---|---|
| العقود والتسعيرات | مراجع زمنية ومدخلات محكومة؛ رفع PDF لا يحوله تلقائيًا إلى عقد معتمد |
| المستفيدون | category/enrollment وbeneficiary_token؛ لا سجل أسماء/هوية شخصية متكامل |
| الآليات والاستثناءات | سياسة صريحة وترتيب exclusion/tariff/cap/copay محدود؛ لا محرر حر لجميع الحالات |
| تنفيذ G5 من الواجهة | غير متاح؛ هارنس اختبار لا يعوض API إنتاجية محكومة |
| المراجعة والاعتراض | أحداث منفصلة ودليل؛ المراحل القابلة للتخصيص والاستئناف الشامل غير مكتملين |

الأسماء الحقيقية قد تُحفظ كجزء من الأصل المصرح، لكن ذلك لا ينشئ نموذج مستفيد مهيكل. يلزم اتفاق على حقول الاسم/الهوية والتشفير والتقليل والصلاحيات قبل تطويرها.

## 7. الإيقاف والاستمرارية

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\laptop.ps1 -Action Stop
```

Stop يحافظ على volumes وملف المفاتيح. Start يعيد التشغيل دون حذف. لا تستخدم `docker compose down -v` أو Docker factory reset؛ يحذفان البيانات المحلية. لا تحذف ملف .env وتعيد توليد المفاتيح فوق قاعدة موجودة؛ ستفقد إمكانية فك الأدلة وMFA. لا توجد أداة نسخ كاملة مضافة في هذه الحزمة؛ راجع [دليل التعافي](G9_DISASTER_RECOVERY_AR.md) قبل أي نقل بيانات موجودة.

## 8. التشخيص

- Docker غير جاهز/Windows containers: شغّل Desktop وLinux containers وWSL2 أولًا.
- منفذ مشغول: اختر -Port عند أول تهيئة أو عدّل قيمة المنفذ فقط.
- فشل البناء: تحقق من الشبكة والثقة بالشهادات ومساحة Docker؛ لا تلغِ TLS.
- رموز MFA مرفوضة: الوقت التلقائي ورمز جديد، دون إعادة استعمال الرمز السابق.
- BLOCKED: أرسل اسم الخطوة والحالة فقط، ونسخ Windows/Docker وSHA؛ لا ترسل .env/secret/التقرير الخام لبيانات الدخول.
- ضغط الذاكرة: أغلق التطبيقات، ابدأ بالـ12 مطالبة، ولا تشغل OCR أو حمل 10K أو المتصفح الآلي بالتزامن. تحميل ملفات كثيفة يحتاج تقييم موارد/قدرات مستقلًا.

## 9. حدود التحقق الآلي

تم التحقق محلياً على Linux داخل Docker من البناء والترحيلات، وحساب قاعدة البيانات المقيّد، وMFA للحسابين، ومنع إعادة الرمز، وإدخال عقد مسودة وتسعيرة وفئة وانتساب ومطالبة اصطناعية عبر API. اجتاز اختبار بقاء المطالبة بعد Stop/Start وإعادة setup دون إعادة تحميل البيانات الأصلية.

يشغّل workflow `Laptop Docker and Windows launcher` فحص صياغة PowerShell 5.1 وعشوائية المفاتيح وACL على Windows، ومشغّل PowerShell الفعلي مع Docker على Linux. يتحقق من منفذ loopback، ثم ينفّذ `check --verify-mfa --verify-inputs` مرة واحدة ويعيد التشغيل. هذا الفحص الاختياري يضيف مراجع مسودة ومطالبة اصطناعية، ويحتفظ بإيصال اختبار خاص؛ Check المعتاد يتحقق أيضاً من بقائها. تكرار فحص MFA يتطلب رمزاً زمنياً جديداً.

هذه الفحوص لا تثبت تشغيل Docker Desktop على اللابتوب الفعلي أو ملاءمة 8 GB للحمل المؤسسي. تُسجّل نتائج Windows/WSL2 والذاكرة والمدخلات الفعلية في تقرير الاختبار الخارجي.

تشغيل محلي اصطناعي لا يثبت الجاهزية للإنتاج أو معالجة أسماء/عقود حقيقية. جميع بوابات القبول تبقى OPEN حتى تحقق العقد والتوقيعات.
