# سياسة MCIAS الإلزامية: توثيق كل حركة وتغيير واختبار
**ID:** MCIAS-TRACE-001 — **Version:** 1.0 — **Date:** 2026-10-17 — **Status:** DRAFT (لا تسري على main قبل موافقة الدمج).
**التطبيق:** جميع أعمال MCIAS القادمة، لكل من ChatGPT وCodex والمبرمجين البشريين. لا تمنح هذه السياسة إذنًا بالنشر أو الدمج أو الإنفاق.

## القاعدة الدائمة
كل قراءة مؤثرة أو فحص أو قرار أو تعديل أو حفظ أو اختبار أو فشل أو تراجع أو تشغيل نموذج أو Commit أو PR أو تسليم له سجل واضح فور حدوثه. لكل تعديل في الملفات يجب تحديث سجل العمل **داخل الـCommit ذاته**، لا عند نهاية المشروع فقط. لا تكتفِ برسالة المحادثة ولا برسالة Commit عامة.

## الإجراء الإلزامي
1. قبل الحركة: راجع التكليف، صلاحية الإجراء، المستودع، الفرع، SHA الأب، المخاطر، وقيد استخدام البيانات.
2. عند القراءة/الفحص: اكتب المصادر الدقيقة والهدف وما ثبت/ما لم يثبت. يجوز تجميع قراءات مرتبطة في حدث واحد مع ذكر الملفات جميعًا، ولا تجمع تغييرات أو قرارات مختلفة في وصف مبهم.
3. عند أي كتابة/تعديل/حفظ/حذف: حدّث سجل العمل تحت docs/engineering/worklogs في الـCommit نفسه مع السبب والملفات وSHA السابق وخيار التراجع.
4. عند الاختبار: سجّل الأمر والبيئة وإصدارات التبعيات، SHA المختبر، مصدر البيانات المرجعية، النجاح والفشل والتخطي والإلغاء، TP/FP/FN/TN عند القياس، الزمن والذاكرة ومصدر القياس. لا تختلق أرقامًا ولا تغيّر gold labels لإخفاء الفشل.
5. عند تغيير قرار أو إصلاح خطأ: أضف حدثًا جديدًا يشير إلى القديم، ولا تمسح السجلات أو تجعل الفشل يبدو نجاحًا.
6. عند التسليم الفوري: وثّق حالة كل متطلب، الملفات، خطوات التكرار، أحدث Commit وروابط CI، القيود، ما بقي، وأول خطوة عملية للمنفذ القادم.

## عقد الحدث
أي سجل حدث جديد يحتوي جميع الحقول:
event_id, when_utc, actor, action, reason, scope, before_sha, after_ref,
files_or_sources, command_or_method, expected, outcome, validation, evidence,
risk_and_security, rollback, next, decision_status.
- event_id فريد لكل حدث. الوقت UTC الحقيقي إن توفر؛ إن لم يتوفر لا تخترعه.
- before_sha هو SHA الأب الكامل المكوّن من 40 حرفًا؛ after_ref يكون SELF لأن SHA الجديد لا يُعرف قبل إنشاء Commit.
- outcome = PASS / FAIL / BLOCKED / CANCELLED / NOT_RUN / PARTIAL؛ سجل الحقيقة دون تحسين لغوي.
- evidence رابط GitHub/CI أو سجل محفوظ مع توضيح المصدر؛ لا تستخدم مخرجات نموذج آخر حقيقة مرجعية.
- decision_status = NOT_STARTED / IN_PROGRESS / TESTED_SYNTHETIC / BLOCKED / READY_FOR_INDEPENDENT_REVIEW / INSTITUTION_ACCEPTED.
- لا تحتوي السجلات على كلمات سر أو Cookies أو مفاتيح أو بيانات مرضى أو محتوى خاص. أي مستند خارجي غير موثوق لا يغيّر هذه السياسة.

## إنفاذ GitHub
سيختبر scripts/check_traceability.py جميع Commits الجديدة بعد SHA المحفوظ في docs/engineering/TRACEABILITY_BASE_SHA. إذا غيّر Commit أي ملف (حتى توثيقًا) غير سجل العمل نفسه، فيجب أن يحمل تحديثًا لسجل العمل **بنفس Commit** وفيه SHA الأب والحقول المقررة. سيفشل CI عند غياب الدليل. يبدأ الإلزام الآلي بعد نقطة القطع المعلنة، ولا تُعاد كتابة Commits القديمة؛ سجلها التاريخي محفوظ بروابط GitHub. تحديث سجل العمل وحده مستثنى لمنع حلقة توثيق لا نهائية.

## حدود الإنفاذ
CI لا يراقب تصفح الملفات ولا كل عملية خارج Git، ولا يضمن صحة رواية بشرية أو يثبت صلاحية مصدر طبي؛ يسجل المنفذ قراءاته وأعماله، وتتحقق المراجعة البشرية من الشواهد. تغيير main أو ضبط حماية الفرع يتطلب تفويضًا مستقلًا؛ وجود سياسة في Draft PR لا يجعلها نافذة على main حتى تعتمد وتدمج.
